# Independent review handoff

The pilot has provisional analyst annotations, not independent human review. The broader
95-case sample is fixed but unannotated. No reviewer has been assigned or contacted.
The intake tool below validates records; it cannot produce or certify human judgments.

## Pilot workflow

Give each reviewer a separate copy of
[the pilot packet](../results/research/corrections/task-audit-reviewer-pack-v1.zip).
Ask each to read `README.md` and `rubric.md`, and complete only `stage-a/stage-a.csv`
before opening `stage-b/`. Both initial reviews must be completed privately, without
seeing the analyst's annotations or each other's sheets. Prior exposure must be recorded
honestly. A reviewer may retain `unclear` judgments; confidence never excludes a case.

As coordinator, freeze each returned Stage A sheet using its actual reviewer identifier.
The following command is a template; no real returned sheets currently exist:

```bash
python scripts/review_task_audit.py freeze \
  --packet results/research/corrections/task-audit-reviewer-pack-v1.zip \
  --manifest results/research/corrections/task-audit-reviewer-pack-v1.json \
  --member stage-a/stage-a.csv \
  --sheet reports/returned-reviewer-a-stage-a.csv \
  --reviewer-kind human --independent-initial \
  --out reports/reviewer-a-stage-a-freeze
```

Use `--independent-initial` only for a reviewer who declares that this is their initial
independent review. Use `--reviewer-kind automated` for automated annotations. Neither
flag establishes expertise, independence or blinding. The tool preserves the submitted
CSV bytes alongside canonical rows, hashes, packet/rubric identity and receipt time.
It rejects missing/duplicate cases, invalid categories, empty required evidence, changed
packets, inconsistent reviewers and existing output directories. Optional notes and
report anchors may be blank. Exact quotes and semantic judgments still need manual checking.

After each reviewer's Stage A is frozen, they can complete `stage-b/case-alignment.csv`
and `stage-b/target-roles.csv`. Freeze those with the corresponding `--member` and
`--sheet`, new output directories, and `--stage-a reports/reviewer-a-stage-a-freeze`.
Stage B requires a prior Stage A freeze from the same reviewer and packet. This records
the submitted sequence; it cannot prove when the reviewer actually looked at a patch.

When both initial human reviews are frozen, compare corresponding sheets:

```bash
python scripts/review_task_audit.py compare \
  --left reports/reviewer-a-stage-a-freeze \
  --right reports/reviewer-b-stage-a-freeze \
  --out reports/pilot-stage-a-agreement.json
```

The comparison preserves categorical disagreements and reports raw agreement, confusion
counts and descriptive Cohen's kappa. Kappa is undefined when both marginals are
degenerate; it is not replaced with perfect agreement. There are no confidence intervals,
independent-sampling claims or automated adjudication. Target-role rows are nested within
cases, so their count is not an independent sample size. Free-text differences need manual
review even when categorical labels agree.

Adjudicate separately after retaining both initial reviews. Record the original labels,
final decision, adjudicator and evidence/reason for each change. Do not overwrite initial
sheets or the benchmark's labels. Any rubric revision must be versioned before broader
annotation begins.

## Broader sample

Use the [broader packet](../results/research/corrections/broader-task-audit-v1/report-only-review.zip)
with its [manifest](../results/research/corrections/broader-task-audit-v1/manifest.json).
The same freeze command accepts `--member wave-1/stage-a.csv` or
`--member wave-2/stage-a.csv`. Both waves were selected in advance; completing one is not
permission to stop based on its labels. Broader Stage B preparation remains separate.

No real agreement result is generated by the tooling tests. Test annotations are explicitly
synthetic and exist only in temporary fixtures. The next study dependency is returned
initial reviews, followed by adjudication and an outcome-analysis freeze. No GPU or paid
model inference is needed for this review workflow.
